# M2 — decision parity of the machine: statement lifetime, write programs, trigger frames, foreign key counters

Generated by `mk_karar_m2.py` from this file (decision tables written from the C source), the opcode-trace differential through the
API drivers (`trdml.py`: every DML statement runs C's own program on the machine; the instrumented C build prints the same event
stream), the page-cache decision traces and gcov of the C driver (`cov_m2.py`). M1's tables (`$S/m1/karar_esligi.md`) still hold
for the read half. C = SQLite 3.54.1 (`sqlite/src`), Rust = worktree `.claude/worktrees/makine`.

## 1. Decision tables

### 1.1 `OP_Program` (vdbe.c 7652-7776)
| # | condition (C line) | outcome C | Rust |
|---|---|---|---|
| P1 | `pOp->p5 != 0` and a frame in `p->pFrame..` has `token == pProgram->token` (7677-7681) | `break`: the sub-program is not run (recursive trigger disabled) | `op.p5 != 0 && self.frames.iter().any(|f| f.token == sp.token)` → `pc += 1` |
| P2 | `p->nFrame >= db->aLimit[SQLITE_LIMIT_TRIGGER_DEPTH]` (7683) | `SQLITE_ERROR` "triggers nested too deep", abort | `self.frames.len() >= host.trigger_depth_limit()` → `Err(Error, "triggers nested too deep")` |
| P3 | `(pRt->flags & MEM_Blob) == 0` (7693) | new frame: child registers `MEM_Undefined`, `nChildMem = nMem + nCsr (+1 if nCsr==0)` | `push_frame`: `a_frame[reg]` empty or register not `MEM_BLOB` → new `FrameRt` with `n_mem + n_csr + (n_csr==0)` cells `MEM_UNDEFINED` |
| P4 | else (7736) | the frame of the previous call: child registers keep their values | the `FrameRt` kept in `a_frame[reg]` is reused |
| P5 | always (7745-7762) | `nFrame++`, save `lastRowid`, `nChange`, `db->nChange`; `p->nChange = 0`; `aOnce` cleared; `aOp` = sub-program | `VdbeFrame{last_rowid, n_change, n_db_change, ...}`, `self.n_change = 0`, `once = vec![0; n_op]`, `cur_sub = Some(sp)` |
| P6 | `pOp = &aOp[-1]; goto check_for_interrupt` (7774) | interrupt / progress check, then instruction 0 | `pc = 0; check_int!(); continue 'frames` |
| P7 | `P4_SUBPROGRAM` names the running sub-program (recursion, stub) | same `SubProgram` object | stub (`is_stub`) → `prog.p_program[n_csr]` |

### 1.2 `OP_Halt` in a frame (vdbe.c 1366-1385) and at the end
| # | condition | outcome C | Rust |
|---|---|---|---|
| H1 | `p->pFrame && pOp->p1 == SQLITE_OK` | `nFrame--`, `sqlite3VdbeSetChanges(db, p->nChange)`, `sqlite3VdbeFrameRestore`, continue after the `OP_Program` | `frames.pop()`, `host.set_changes(n_change)`, `restore_frame`, `pc = f.pc + 1` |
| H2 | H1 and `pOp->p2 == OE_Ignore` | continue at `P2` of the calling `OP_Program` | `pcx = f.prog_p2 - 1` |
| H3 | `pOp->p1 != SQLITE_OK` (also in a frame: RAISE(ABORT/FAIL/ROLLBACK)) | `p->rc`, `errorAction = p2`; message from `P3` register / `P5` constraint text / `P4`; `sqlite3VdbeHalt` | `Err(e)` with `conflict_effect` from P2; `Vdbe::halt` unwinds the frames |
| H4 | `sqlite3VdbeFrameRestore` (vdbeaux.c 2827) | `closeCursorsInFrame`; `aOp`, `aMem`, `apCsr` of the parent; `db->lastRowid`, `p->nChange`, `db->nChange` restored | `restore_frame`: cursors freed in slot order, parent state back, `host.set_last_rowid`, `host.set_db_changes`; the child run time goes back to `a_frame[f.reg]` |
| H5 | `closeAllCursors` with frames (vdbeaux.c 2853) | restore the ROOT frame (cursors of the innermost frame closed), root cursors closed, then the deleted frames (`pDelFrame`, outermost first) close theirs | `Vdbe::halt`: innermost cursors, `frames.pop()` / `restore_frame` to the root, root cursors, then the cursors of the frames in between in order |

| C | condition | outcome | Rust |
|---|---|---|---|
| `OP_Once` (2778) | `p->pFrame` | bit `iAddr` of `pFrame->aOnce`: set → jump; else set it | `!frames.is_empty()`: `once[pc] != 0` → jump, else `once[pc] = 1` |
| | no frame | `aOp[0].p1 == pOp->p1` → jump; else copy | as M1 (`init_p1`) |
| `OP_NewRowid` (5802-5813) | `P3 != 0` and `p->pFrame` | AUTOINCREMENT register of the root frame | `frames.first_mut().a_mem[p3]` |
| `OP_MemMax` (7860-7867) | `p->pFrame` | `pIn1` in the root frame | `root_mem(p1)` |
| `OP_Param` (7790) | always in a frame | `pFrame->aMem[p1 + pFrame->aOp[pFrame->pc].p1]` shallow copy | `f.a_mem[(op.p1 + f.prog_p1)]` clone |

### 1.6 Opcode trace conventions of the instrumented C build that the machine mirrors
C prints the last instruction against `p->aOp` as it is *after* the instruction ran: `OP_Program` (now the sub-program), a frame's
`OP_Halt` (now the parent) and the instruction that fails inside a frame (`sqlite3VdbeHalt` restored the main program) are out of
range and not printed — unless the same sub-program calls itself (then the address is in range and printed). The machine prints
exactly these. C prints the statement text again at the `OP_Init` of a sub-program; so does the machine. The last instruction of a
halted statement is printed by C after `releaseMemArray`: a register that holds a heap buffer (`szMalloc`) shows `U`; the machine
does not model `szMalloc`, the comparison masks that line's register digests where C shows `U` (`last_line_masked`).
